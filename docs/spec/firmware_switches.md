# Firmware switches: every setting below Debian

The user asked on 10-23 for every firmware-level switch and setting in one place, as [area_switches.md](area_switches.md) has the hardware's. This page lists everything below Debian that Tanager builds, patches or configures: OpenSBI, U-Boot, the device trees, the kernel command line, the board's boot-mode record and the A53's hand-over, and the registers firmware writes for the hardware.

- **For each setting:** what it does, where it is set, its value in the release image, whether it is KV260-specific or general, how to turn it off or change it (and what that does), and the decision behind it.
- **The release image** is rc3u095r's `p1:/tanager/` (the M8 release image of record, 10-23): `fw_jump.bin` `62349a65…` (OpenSBI 1.9 with patch set tg1), `payload.bin` `459992b8…` (U-Boot d4), `tanager.dtb` `18afd230…` (four harts), `tanager-h01.dtb` `15cd197c…` (one core's two harts), and `riscv.scr` built from `sw/d4mode/riscv.cmd`. Against rc2's package only the bitstream, `riscv.scr`'s image header and the README differ. u100's shipped with OpenSBI `b0094d23…` and took tg1 on the board later (`fpga/kv260/board/u100/tg1_install.txt`).
- **Rebuilding it:** `sw/d4mode/riscv_package.sh` makes RISC-V mode's package of a `build.tcl` run. From main it rebuilds rc3u095r's every file byte for byte, given spikes-2's run (the bitstream), the README template `sw/d4mode/package/README-rc3.in` and `riscv.scr`'s image time (`SOURCE_DATE_EPOCH=1792805748`). `sw/build_opensbi.sh` rebuilds `fw_jump.bin` byte for byte too; `sw/build_uboot.sh d4` rebuilds `payload.bin` but for U-Boot's build-time string (8 bytes, "Oct 19 2026 - 03:25:00 -0700").
  - **Since DR-192's MAC change** (board MR43), the trees carry no MAC and `riscv.cmd` sets the board's own at boot. So a package from main differs from rc3u095r in its trees and `riscv.scr`, and rc3u095r itself carries this board's MAC.
- **General** settings hold for any Tanager board; the **KV260-specific** ones (below) come from this board's PS, peripherals and boot firmware, and a build for another board replaces them. The hardware's switches are in [area_switches.md](area_switches.md), and its platform tunings (the L2's write-back batching) in its §Platform tunings.
- **Not here:** Debian itself (its kernel, `sw/debian/stage_d_prep.sh`'s modules and getty, DR-168) and the A53's own boot firmware, which Tanager does not change (QSPI keeps `K26-BootFW-01.02` in both slots, and its U-Boot environment was never saved). DR-147's advance approval for boot-firmware changes covered OpenSBI's tg1 ([soc.md](soc.md) §5).
